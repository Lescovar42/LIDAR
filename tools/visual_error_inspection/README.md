# Visual Error Inspection

This package adds a non-destructive diagnostic for the current Tillamook U-Net
baseline.

It does **not**:

- rebuild the LiDAR dataset;
- modify NPZ patches;
- retrain the model;
- change train/validation/test splits;
- change the selected threshold;
- overwrite the existing `evaluate.py` outputs.

## Install

Extract the ZIP directly into the repository root:

```text
F:\LIDAR
```

After extraction, these tracked paths should exist:

```text
oregon\diagnostics\inspect_visual_errors.py
oregon\tests\test_inspect_visual_errors.py
tools\visual_error_inspection\RUN_TILLAMOOK.ps1
tools\visual_error_inspection\SELF_TEST.ps1
```

Run the tests:

```powershell
cd F:\LIDAR

powershell `
  -ExecutionPolicy Bypass `
  -File .\tools\visual_error_inspection\SELF_TEST.ps1
```

Commit the new paths so the laptop and Machine 2 stay identical:

```powershell
git add `
  .\oregon\diagnostics\inspect_visual_errors.py `
  .\oregon\tests\test_inspect_visual_errors.py `
  .\tools\visual_error_inspection

git commit -m "Add representative visual error inspection"
git push origin main
```

## Run

From the repository root:

```powershell
cd F:\LIDAR

powershell `
  -ExecutionPolicy Bypass `
  -File .\tools\visual_error_inspection\RUN_TILLAMOOK.ps1
```

The wrapper runs against:

```text
dataset_tillamook_probe_15m
patches_boundary_aware.csv
training_output_tillamook_15m_boundary\best_model.pt
threshold 0.65
validation split
```

No training is performed.

### `professor_comparison.png`

Three representative rows:

1. representative good positive;
2. false-positive-dominant case;
3. false-negative-dominant case.

Columns compare:

1. LiDAR hillshade;
2. ground truth;
3. prediction at 0.50;
4. prediction at 0.65;
5. error map at 0.65.

The error-map legend is:

```text
yellow = true positive
red    = false positive
green  = false negative
blue dashed/faint = ignored label pixels
```

Ignored pixels are intentionally not painted solid blue.

### Detailed representative cases

The diagnostic tries to keep selected cases below 30% ignored area. If too few
eligible positive samples exist, it relaxes that constraint and records the
actual limit in `error_summary.json` and `error_summary.md`.

It selects:

```text
representative_good
representative_median
true_boundary_typical
false_positive_dominant
false_negative_dominant
```

### Quantitative error inspection

The report also compares errors by:

- LiDAR tile;
- boundary-aware `coverage_class`;
- actual in-patch label-boundary presence;
- dominant patch error type;
- terrain-channel means for TP, FP, FN, and TN pixels.

These diagnostics help distinguish broad model overprediction from
boundary-specific failure and tile-specific failure.

Pak Rasyid's requested output is generated by:

cd F:\LIDAR

Open:

```powershell

  .\oregon\evaluation_tillamook_15m_prediction_maps\professor_predicted_vs_gt.png
```

The contact sheet is deliberately direct:

```text
Ground Truth | Predicted Mask @ 0.65 | Difference Map
```

It also exports all validation patches and one stitched, cropped validation
mosaic per LiDAR tile:

```text
evaluation_tillamook_15m_prediction_maps\
  professor_predicted_vs_gt.png
  professor_cases\
  all_patch_maps\
  stitched_tile_maps\
  stitched_tile_geotiffs\
  stitched_tile_metrics.csv
```

The stitched tile images are not full-LAZ inference. They combine only the
validation patches present in the manifest. Gray gaps are unevaluated.

GeoTIFF classes:

```text
GT / prediction:
0   background
1   landslide
255 nodata / ignored

Error:
0   true negative
1   true positive
2   false positive
3   false negative
255 nodata / ignored
```
